本文件将第一版需求展开为输入、处理流程、输出、人工确认点和验收标准，供运营、开发和测试共同核对。业务范围沿用已确认的内部团队及自有美国站店铺；六个 Agent 与四个配套模块组成完整工作流程。

## 通用记录与验收约定

### 输入和输出的共同要求

| 信息组 | 每条业务记录必须能回答的问题 |
| --- | --- |
| 对象 | 属于哪个站点、店铺、ASIN、SKU、规格或套装；哪些标识尚未取得。 |
| 来源与时间 | 数据来自哪个页面、同步批次或人工输入；业务统计期间及采集时间是什么。 |
| 数据性质 | 是店铺实际数据、公开参考区间、选品测算、预测，还是测试数据。 |
| 版本与依赖 | 使用哪个商品事实、配置、报价、费用规则、模型或工作流版本；结果引用哪个输入。 |
| 状态与原因 | 是否完整、过期、失败或待确认；缺少什么、影响哪一步、由谁处理。 |

字段未知与数值为零分别保存。公开购买量原文与解析值并存；金额带币种，数量带计量单位，尺寸和重量注明是否为包装参数。单件商品可能是一套销售包装，必须与 Listing 的销售单位一致。

### 执行状态和业务结论分开

任务状态描述工作进度：待执行、处理中、待人工、成功、失败或部分成功。选品业务区描述判断结果：候选、待确认、已排除。人工选中后另记“已选中”，供下游启动；完成搜图不代表商品已通过最终审核。

进入待确认时必须给出具体问题、证据、可采取的动作和恢复位置。确认一个事实后，只重做受该事实影响的步骤；修改规格可能影响货源、物流、利润及内容，旧版本保留。

### 人工确认记录

统一记录确认对象与版本、问题、修改前后值、决定、理由、操作人和时间。确认权限由团队配置，第一版不强制不同人多级审批。系统已能确定的普通步骤自动继续，不逐步要求运营点击。

### 验收证据

每个模块的验收分为规则样例和真实接入两部分。样例中的价格、费用、销量仅用于验证逻辑，不能当作当前平台收费或真实经营数据。真实采集、模型生成、店铺同步及平台提交须提供实际返回和可核查结果。

模型判断采用业务标注样本核对“自动通过、待确认、排除”的分流及证据；样本规模和误判率目标由实测后确认。本文不承诺选品收益、预测准确率、全站覆盖率或每天一万条的稳定处理能力。

## M01 商品采集与竞品查询

对应基础需求：DQ-01 至 DQ-05；DT-01 至 DT-03。

### 输入

| 输入 | 来源与约束 |
| --- | --- |
| 采集范围 | 美国站公开商品页面及采集发现入口；已扫描 ASIN 持续跟踪，不购买第三方选品数据库。发现入口和覆盖率需接入验证。 |
| 筛选条件 | 近 1—12 个月上架、当前售价区间、FBA／FBM、单 ASIN 近期销量门槛；全类目一起筛。 |
| 运行参数 | 默认每 24 小时更新；查询范围、更新时间、排序方式均可配置，任务保存配置版本。 |
| 已有记录 | 站点与 ASIN、父子关系、上次快照、历史排除及核价记录；不存在时创建新商品记录。 |

### 处理流程

1  发现并去重。把发现的链接规范到站点和 ASIN，查询已有记录；新 ASIN 入库，已有 ASIN 更新快照。已排除商品仍保留在持续采集范围。

2  提取字段。记录标题、主图、品牌、类目、上架时间、当前售价与币种、发货方式、公开购买量、可得排名及父子关系。每项保留来源与时间，失败不写成零。

3  核对销售口径。保存公开购买量原文及可证实的上下界；“300+”只表达至少 300 的公开参考，不伪装成精确销量或严格滚动 30 天成交件数。归属不明确时不能用于单 ASIN 达标。

4  执行筛选。按所选月份判断上架时间，按链接当前售价判断价格，按发货模式及销量参考判断其余条件。确定不符的保留不匹配原因；关键项未知的进入待确认结果。

5  排序并交接。匹配结果默认按销量参考值从高到低展示，交给 M03。建议待确认：同值时按 ASIN 稳定排序，未知值不按零参与排序。

6  持续更新。每个周期追加采集记录，保留旧值与失败原因；新商品发现与已知商品复抓均报告成功数、失败数和缺项数，不把部分采集标为全量完成。

建议待确认：上架窗口按查询时刻向前推 N 个自然月，售价上下限均包含边界。站点时区、促销和优惠券的取价方法需先确定；页面日期只有日精度时，不推造具体上架时刻。

## M01 输出 人工确认与验收

### 输出

一份商品查询结果和一份采集批次记录。每行商品包含基础字段、匹配或未知原因、原始购买量、来源时间和详情入口；批次包含范围、起止时间、成功失败数量和下一次计划更新。查询快照可供后续任务引用。

历史页展示实际积累的价格、购买量区间及其他可得指标。相邻滚动购买量的差不能生成当日销量，首次采集前的历史保持缺失。

### 人工确认点

| 触发条件 | 人工动作 | 确认后的处理 |
| --- | --- | --- |
| 日期、价格、发货模式或销量归属不明 | 核对来源并补充事实；也可暂缓。 | 重算相关筛选条件，记录补充依据。 |
| 父体购买量与子体混淆 | 确认属于目标 ASIN，或保留未知。 | 未确认前不将父体总量算作单品销量。 |
| 采集不可用或持续缺项 | 处理登录或来源问题；确认是否更换入口。 | 恢复采集并保留失败期间，不补造数据。 |

### 验收标准

| 编号 | 给定条件与动作 | 通过标准 |
| --- | --- | --- |
| M01-A01 | 输入近三个月、FBM、20—35 美元、门槛 300。 | 只按上架日期筛三个月，价格使用当前值；有明确单 ASIN“300+”证据可作参考达标，结果保留区间标签。 |
| M01-A02 | 商品上架已一年，但最近三个月有销量。 | 不因销量时间符合就通过上架条件，显示上架时间不符。 |
| M01-A03 | 购买量为 200+，门槛为 300，无法确定上界。 | 不能宣称明确不足 300；标为不能确认达标，允许人工复查。 |
| M01-A04 | 父体 500+，目标子体销量未知。 | 目标子体不能自动通过销量门槛，保留父子关系与待确认原因。 |
| M01-A05 | 同一 ASIN 重抓且其中一次请求失败。 | 商品不重复；保留各次快照和最后成功日期，失败不覆盖成零。 |
| M01-A06 | 查看积累一天的商品去年同期销量。 | 如实显示无该历史；不从今天购买量反推去年或精确日销量。 |

## M02 店铺同步与测试数据管理

对应基础需求：ST-01 至 ST-02；DT-04。

### 输入

| 输入 | 来源与约束 |
| --- | --- |
| 店铺授权 | 内部自有美国站账号授权、可访问店铺和权限状态；不在普通业务界面展示密钥。 |
| 商品与销量 | 自有商品、SKU、ASIN、业务日期及真实售出数量；订单级或汇总级采用实际可取得的资料，不臆造明细。 |
| 库存 | 实际返回的可售、占用、不可售等数量及口径；记录时间和适用发货模式，缺失项单独标识。 |
| 同步参数 | 店铺范围、首次回溯期间、增量频率、订单状态和时区。具体值待业务确认与账号能力验证。 |
| 测试数据 | 暂代 ERP 的采购成本、实际物流费用、在途数量和预计到货等；按店铺、SKU、日期关联，独立标记测试批次。 |

### 处理流程

1  校验授权。确认店铺归属和读取权限，展示可用范围；授权无效时暂停该店铺同步，其他店铺可继续。

2  同步商品与销量。完成首次回溯后按配置增量读取；根据实际来源的业务键去重。源数据更正时保留修订记录，不能把同一订单的多次同步当作多笔销量。

3  同步库存。保存不同库存状态及更新时间；可售数已扣除占用时，不再次扣减。不可售和未到货数量不计为当前可售。

4  校验测试数据。按同样的商品、单位和时间规则检查测试输入，但放入独立数据批次。测试行不能覆盖真实销量、真实库存或假装已完成采购。

5  交付数据。M06 取得真实销售历史和库存，M07 另外取得测试成本与在途；M08、M09 显示各自来源。派生结果引用测试字段时同步显示“含测试数据”。

建议待确认：销量按订单商品的售出件数建立基础指标，取消、退款和退货分别保留调整依据；是否用下单日或发货日计入基础销量，须在预测前选定。

## M02 输出 人工确认与验收

### 输出

输出自有商品档案、带期间的销量数据、按状态区分的库存快照、独立测试数据批次，以及按店铺展示的同步记录。下游可查看最后成功时间、覆盖日期、缺失日期、失败原因与数据修订版本。

### 人工确认点

| 触发条件 | 人工动作 | 确认后的处理 |
| --- | --- | --- |
| 首次接入或授权失效 | 完成授权并确定同步店铺。 | 按批准范围同步，未授权店铺不读取。 |
| SKU 映射冲突或统计口径不明 | 核对商品对应关系、销量口径或库存状态。 | 修正映射后重算受影响结果，保留修订来源。 |
| 测试批次待启用 | 检查商品、成本、在途和日期，明确测试用途。 | 启用后只影响引用该批次的新任务。 |

### 验收标准

| 编号 | 给定条件与动作 | 通过标准 |
| --- | --- | --- |
| M02-A01 | 用真实授权店铺同步一段已知期间。 | 商品、SKU、销量和库存可与同口径后台记录核对；记录实际覆盖日期和同步成功证据。 |
| M02-A02 | 同一数据批次被重复同步。 | 销量不翻倍，商品不重复；同步重试有记录。 |
| M02-A03 | 来源可售 80，另列占用 10，且可售已扣占用。 | 交给补货的当前可用库存为 80，不能再次扣成 70。 |
| M02-A04 | 授权失效或某天数据缺失。 | 显示失败或缺失日期，保留旧数据时间；不把缺失日认定为零销售。 |
| M02-A05 | 真实库存 80，另有测试在途 50。 | 当前实际可售仍为 80；补货使用在途时整体标为含测试数据，并能定位该 50 件。 |
| M02-A06 | 修改或停用测试成本批次。 | 真实经营记录不变；旧方案仍指向原输入，新任务按所选有效批次处理。 |

接入验证：FBA 与 FBM 库存可获取的字段及精度可能不同，必须逐项验收；同步频率和历史回溯长度不以演示数据代替。

## M03 选品 Agent

对应基础需求：SE-01 至 SE-08；SO-01 至 SO-03；PR-01 至 PR-03；LG-01 至 LG-04；IP-01 至 IP-04。

### 输入

接收 M01 的匹配商品、主图标题、售价、品牌和发货方式，以及历史核价、排除记录。另读取当前任务的筛选偏好、利润门槛、1688 货源、货代报价表、常用渠道、平台费用规则、汇率及广告仓储参数。缺项必须保留未知。

### 处理流程一 初筛与货源核对

1  检查历史。确认是否同一商品及同规格。已查过不能做且没有符合复查条件的变化时复用排除原因；不凭标题相似自动合并。

2  图文初筛。明显服装、包包、球衣、家具大件等按规则排除；品牌或用途风险有明确证据时按对应规则处理。普通气球、烧杯不能仅凭名称被判为违禁。

3  保留可能商品。小体积、轻重量、带电、无明显品牌、新颖差异化和简单结构作为排序偏好。没有固定尺寸重量上限；拿不准时待确认，不因偏好缺失直接排除。

4  查询货源。候选自动进入 1688 搜图和详情核对。确认已有同款同规格货源时先复用，再查当前单件拿货价；失效、规格不符或价格明显变化时重新搜图。

5  逐项比对。核对外形、功能、型号、尺寸、销售包装件数及适用规格，保存目标商品和每个货源的对照结果。配件、裸机与整套商品分开，不用外观相近替代规格一致。

6  确定拿货价。比较可比货源的实际单件价格、SKU、购买条件和时间；FBM 与 FBA 都用单件价。不能直接用最低展示价、批量阶梯价或未证实的模型估价。无法确认时转人工。

建议待确认：比较货源的目标数量与“价格明显变化”阈值可配置；未设定前不以固定比价家数或涨幅触发硬性排除。实际仅找到一个可靠货源时显示比较不足，由运营决定是否继续。

## M03 处理流程二 利润与风险

### 费用和利润处理

7  计算物流。按包装尺寸、重量、商品属性及报价规则选用指定常用渠道。保存计费重量、分段费用和适用依据，带电商品须确认渠道接受。资料或渠道不明时待确认。

8  检查总周期。FBM 按采购到买家签收的常规最长时间判断，初始上限 30 天；FBA 按采购到入仓可售判断，初始上限 90 天。不能只取空运或海运段，且不通过换渠道凑利润。

9  计算平台费用。根据站点、类目、售价、包装尺寸重量选用适用规则，保存来源和生效版本。类目或档位不清晰、规则缺失时不填零。

10  核算并分流。各成本统一币种后计算下式。未舍入的利润率达到任务门槛才继续风险检查；成本明确但不足则排除，成本不确定则待确认。

FBM 总成本包括单件拿货价、头程、尾程和平台抽点。FBA 总成本包括单件拿货价、海运头程、亚马逊配送费、平台抽点、分摊的单件仓储费和预留广告费。两种模式分别采用对应总成本。

FBM 当前口径为不投广告。FBA 计划投放时初始预留售价的 10%，明确不投放计 0，计划不明待确认；仓储初始按 2 个月分摊。两项均可按商品调整。买家可能额外支付的运费不纳入基础收入。

### 商标和外观专利处理

11  检索商标。按参考品牌查询美国站相关商标，保存查询词、来源、时间及命中记录；查到相关商标进入待确认，由运营决定是否尝试差异化或套装。

12  检索与对照专利。用英文产品词及关联词查找外观专利，汇总记录和附图，逐张与实际拟采购产品图对比，指出相同结构、差异及遗漏可能。检索失败不等于未检索到。

13  提交人工选品。保留运营“人工认为相似度约 50% 以上即放弃”的经验。模型相似分数映射未验证前不直接套用该百分比；不确定项提交人工，不给出保证不侵权的结论。

| 触发条件 | 需要确认的内容 | 恢复位置或结果 |

### 历史商品复查

仅因利润不足而放弃的商品，售价上涨后先使用新售价及保存的成本依据粗算；按售价比例收取的费用也随新售价重算。预计达标时进入待确认，再核实当前 1688 拿货价。售价未明显变化的先跳过，历史核价不覆盖。

复用货源不等于复用利润结论。新链接必须按自己的售价和 FBA／FBM 重算；其他已知风险不能因利润回升自动清除。恢复处理或改规格均生成新的关联记录。

## M04 产品内容生成 Agent

对应基础需求：CG-01 至 CG-04；KW-01 至 KW-04；QC-01 至 QC-03；VD-01 至 VD-02。

### 输入

| 输入 | 来源与约束 |
| --- | --- |
| 确认的商品事实 | 来自 M03：目标规格、功能、尺寸、材质、套装件数和图片。事实不明时待确认，不从竞品卖点推定自己具备同样能力。 |
| 参考竞品 | 运营选用的链接及可取得的主图、附图、标题、五点、描述与 A+。参考来源和缺失项可查看。 |
| 内容与品牌要求 | 目标站点语言、自有品牌及允许使用的品牌信息、风格、卖点优先级；品牌属性不明时待确认。 |
| 关键词资料 | 有来源的相关词、可核实的排序依据、统计期与站点；模型建议词单列。前 20 个为初始研究清单目标。 |
| 生成配置 | 文案与图片模板、附图数量、A+模块、视频参数、ComfyUI 工作流及模型版本；具体初值仍待选择。 |

### 处理流程一 图文与关键词

1  锁定事实版本。人工选品后创建内容任务，保存事实、参考资料和配置。自己商品的事实优先于竞品；缺少关键规格时先完成澄清。

2  提取参考内容。获取可用竞品素材，分析构图、文案结构和表达风格，生成对应提示词。参考图不能直接当作自己商品的成品图，不能继承不属于自己的功能。

3  整理关键词。去除无关词和不应使用的品牌词，保留来源与排序依据。排名定义未确认或数据不足时明确标记，不把生成词包装成真实热搜词。

4  生成 Listing。相关高优先级词优先安排在标题，再到五点、描述；保持句子通顺和事实一致。同时生成研究词清单和符合适用规则的后台提交字段。

5  生成图像与 A+。按确认的外形、配件与包装制作白底主图、附图和 A+模块；图片文字与文案共用商品事实。每项产出实际文件或可查看模块。

6  校验与局部修改。检查事实、品牌词、规格件数和平台适用约束；定位到段落、图片或 A+模块。能确定的错误局部替换后重检，无法确定的交人工。

## M04 修改关联与验收

### 内容变化后的处理

改动只生成新版本。改商品规格、件数或功能时，相关文案、图片、A+和视频全部重新检查；改白底主图时检查视频是否依赖旧图；改 Listing 卖点时检查视频脚本及画面。仅调整某张附图排版时，无关文案不被无提示重写。

已有人工确认只覆盖当时选定的版本。后续修改的内容须重新审核，不能借用旧确认直接进入发布。M05 可以看到本次修改范围及此前已提交版本。

### 验收标准

| 编号 | 给定条件与动作 | 通过标准 |
| --- | --- | --- |
| M04-A01 | 选中单支打蛋器，竞品图片为带支架三件套。 | 最终文案、主图、附图、A+和视频均按实际单支规格；不把参考配件加入销售承诺。 |
| M04-A02 | 可用关键词只有 12 个，其中含第三方品牌词。 | 剔除不适用品牌后如实交付剩余清单及缺口；不编造排名、搜索量或竞品私有后台词。 |
| M04-A03 | 选定关键词有明确排序来源。 | 高优先级相关词先考虑标题，其次五点和描述；能查看使用位置，语义和事实不因塞词失真。 |
| M04-A04 | 研究清单超过平台后台字段的适用限制。 | 研究词清单保留；提交字段按实际规则整理，不直接把所有完整词组硬塞入字段。 |
| M04-A05 | 某附图文字出现应移除品牌，其他内容正确。 | 能定位并修改该图，保留旧版；改后重新检查品牌和规格，不重写无关合格内容。 |
| M04-A06 | 普通词与注册品牌同名，或出现自有品牌。 | 无法确定时交人工，不按字面一律删除或替换；确认依据可追溯。 |
| M04-A07 | ComfyUI 返回任务编号但没有有效视频文件。 | 不能记为视频生成成功，显示处理中或失败；重试保留已完成图文。 |
| M04-A08 | 取得真实生成视频并修改原白底主图。 | 视频可实际播放；修改后提示其依赖旧图，重新选择或生成并审核对应版本。 |
| M04-A09 | 八项中 A+或视频未完成。 | 显示缺失项和部分完成状态，不将整套内容记为已交付完成。 |

接入验证：关键词免费来源与排序、目标账号可用 A+模块、图像模型和 ComfyUI 工作流。图片尺寸、附图数量、视频时长比例及字幕配音由配置确定，本文不擅自固定。

## M05 亚马逊草稿与确认发布

对应基础需求：PB-01 至 PB-06。

### 输入

| 输入 | 来源与约束 |
| --- | --- |
| 目标店铺 | 已授权店铺、站点及具备发布确认权限的成员；不能仅凭 ASIN 推定店铺。 |
| 商品创建资料 | SKU、商品类型、品牌、编码、规格、变体等实际需要的资料；要求来自目标账号和类目适用规则。 |
| 确认的内容包 | M04 中选定的文字、图片、A+和视频版本，以及校验和人工内容审核记录。 |
| 提交与确认记录 | 此前草稿标识、平台返回、已提交版本及待修改项；提交草稿与正式发布确认独立记录。 |

### 处理流程

1  预检查。验证店铺、权限、商品标识、必填属性和素材版本。缺编码、品牌依据、变体资料或存在未解决校验问题时列出缺项，不能补造资料。

2  保存平台草稿。通过已验证的实际路径向目标账号提交草稿，记录平台标识和返回；能够回查草稿内容后才标为草稿已保存。

3  等待用户确认。展示目标店铺、SKU、价格等提交资料和内容预览；用户核对具体版本后确认发布。未确认不能进入正式发布动作。

4  分别提交素材。Listing、A+和视频按各自实际可用路径处理，分别记录账号资格、提交、平台审核和生效状态。某项受限时说明原因。

5  核实平台结果。根据平台可核查结果更新成功、处理中、部分成功或失败状态；提交成功不等于已生效。可定位错误并修复后重试。

6  修改与重试。利用已有平台标识定位同一对象，先核对上次是否成功，避免因超时重复创建。改稿形成新内容版本和确认记录。

### 人工确认点

运营补齐商品创建资料并核对平台草稿；有权限的人对指定店铺、商品和内容版本确认发布。A+或视频缺乏资格、原生草稿路径受限时，需要确认实际替代流程，系统不能自行改成直接上架。

### 输出

| --- | --- |

| 编号 | 给定条件与动作 | 通过标准 |
| --- | --- | --- |
| M05-A01 | 真实账号完成一次商品草稿提交。 | 能在目标账号回查草稿及对应内容；本地文件、预校验或库存设零不算通过。 |
| M05-A02 | 草稿已保存但用户未确认发布。 | 不存在正式发布调用或动作；状态保持待确认。 |
| M05-A03 | 内容版本 V1 已确认，随后更换主图为 V2。 | V1 的确认不自动覆盖 V2；展示差异并重新确认改动版本。 |
| M05-A04 | 缺少平台必需的商品编码或规格属性。 | 明确列出缺项并暂停，不能随机补造编码或发错变体。 |
| M05-A05 | Listing 成功，A+被拒绝，视频处理中。 | 三项分别显示，整体为部分完成；不能整套宣称发布成功。 |
| M05-A06 | 提交超时后再次点击重试。 | 先核对已创建对象，用同一任务恢复；不会重复创建相同商品。 |
| M05-A07 | 账号无法形成目标草稿流程。 | 该接入验收不通过，记录具体限制和备选流程待确认，不改口称功能已完成。 |

接入验证优先于实施承诺：用户是在本系统还是卖家后台点击最终确认，需要验证实际平台能力后选定。A+与视频的发布入口不能假设与 Listing 完全一致。

## M06 销量预测 Agent

### 输入

### 处理流程

1  检查预测任务。确认对象与用途；选品可主动调用，采购在缺少可用预测时联动调用。已有结果必须匹配商品、日期和经营条件，不能无提示复用过期版本。

2  检查输入质量。核对期间覆盖、口径、缺失和缺货影响。缺历史不填造销量；没有足够依据时输出数据不足及需要补充的内容。

3  形成预测。大模型调用数据与分析工具，计算工具产生数量和日期。候选新品用可比资料和经营假设推估；在售商品以真实历史为主，解释变化因素。

4  检查时间覆盖。FBA 采购须覆盖采购至可售的等待时间及后续销售期；不能用短于需求期的结果直接支持采购。远期预测单独说明不确定性。

5  保存并交接。保存输入快照、方法、假设和预测版本，提供给 M03、M07、M08、M09。测试数据影响具体字段时标明，不与真实预测评估混用。

6  回溯评估。预测期间结束后，以同口径真实销量对比原预测，计算误差并保留原值。回测只用预测时已存在的数据，避免使用未来信息。

建议待确认：先采用保守、基准、乐观三种情景表达新品不确定性，三者不默认称为统计置信区间；初次采购选择哪种情景由运营确认。

## M06 输出 人工确认与验收

### 输出

预测结果包含商品与用途、起止日期、期间销量、可用的逐日或逐周分布、数据截止日、输入与方法版本、假设、情景、缺项和数据性质。预测曲线合计应与期间总量一致；只得到总量时，不虚构精细时间曲线。

评估结果包含预测区间、同口径实际数量、误差指标及缺货异常说明。WAPE 为绝对误差之和除以实际销量之和；实际合计为零时不可计算。MAE 为绝对误差的平均值。建议待确认：数量偏差采用预测合计减实际合计，正数代表高估。

### 人工确认点

商品或比较对象不明确时确认可比范围；计划售价、广告安排和预测期间不清楚时补齐假设；数据不足或用于采购的情景需选择时交运营判断。日常已具备条件的预测可自动完成，不逐次强制审批；采购方案仍由 M07 人工确认。

### 验收标准

| 编号 | 给定条件与动作 | 通过标准 |
| --- | --- | --- |
| M06-A01 | 新品只有竞品 300+ 区间，无自有销量。 | 不能直接预测自己也卖 300；说明输入局限、采用假设和数据不足，不能编造历史曲线。 |
| M06-A02 | 在售商品有真实销量，但部分期间缺货。 | 注明缺货可能压低实际销量；不得把缺货日直接当作真实需求为零。 |
| M06-A03 | 计划 FBA 总等待 90 天、到货后覆盖 30 天。 | 预测或需求评估覆盖相应 120 天窗口；资料不足时待确认，不用仅 30 天预测静默替代。 |
| M06-A04 | 逐周数量 10、20、30，对应期间总量。 | 期间总量为 60，单位及日期一致，可追溯输入与方法。 |
| M06-A05 | 回测预测为 12、8；实际为 10、10。 | 绝对误差合计 4，WAPE 为 20%，MAE 为 2；建议口径的数量偏差为 0。原预测不被修改。 |
| M06-A06 | 实际销量合计为零或实际数据缺失。 | 区分零与缺失；WAPE 不强算为零，缺失不能当成零完成效果验收。 |
| M06-A07 | 采购期间或商品售价变化，旧预测不再适配。 | 提示重算或新建预测；旧结果保留，M07 可识别版本变化。 |

预测方法、最少历史长度、曲线粒度、误差目标和结果有效期仍待实测确定。验收首先检查来源、计算和边界正确，不以大模型“看起来合理”或虚构精度作为通过条件。

## M07 补货 Agent

对应基础需求：RP-01 至 RP-05。

### 输入

| 输入 | 来源与约束 |
| --- | --- |
| 采购对象与预测 | 首次采购或在售补货；商品、规格、店铺及有效预测版本、日期、情景。 |
| 库存与在途 | 真实可售、占用和状态口径；在途数量及预计可售日期暂用测试数据。未到货不能提前成为可售。 |
| 周期与库存策略 | 采购及运输入仓总周期、目标销售覆盖期、安全库存；数值由运营配置。 |
| 采购约束 | 起订量、整箱数量、供货条件、预算和供应商；未知条件不能默认零或无限。 |
| 费用依据 | 单件采购价、物流及纳入的其他费用、币种与汇率。ERP 未接入部分用测试值，并向方案传递标识。 |

### 处理流程

1  验证预测。匹配商品、用途、期间及输入条件；缺少有效预测时调用 M06。预测未满足采购时间跨度或关键事实不明时暂不形成可确认数量。

2  按时间测算库存。使用真实当前可售和预测需求，按预计可售日期加入在途，识别预计缺货日期。晚于缺货日的到货不能掩盖前面的断货风险。

3  形成基础数量。建议待确认：到货后覆盖期的预测需求，加安全库存，扣除到货前预计可用库存及覆盖期其他有效在途，最低为零。在途按时间只计算一次；断货损失不自动视为欠单累加。新品首次采购只计预计可售后的销售窗口。

4  处理采购约束。建议待确认：正需求按起订量和整箱要求向上取整；零需求不因起订量而强行采购。预算不足时列出缺口和备选，不静默违反箱规或自动减量。

5  核算金额和日期。用计算工具核算采购额、物流额、总资金及建议下单日期。若当前下单也无法按需到货，标记延误风险，不输出不可执行的过去日期作为正常建议。

6  提交方案。显示数量、资金、风险和依据，交人工修改确认。修改数量、日期或成本后重新检查约束和金额，保留原建议。确认前提示输入发生的变化。

安全库存的计量方式、覆盖期和预算分配策略尚未确认。上述数量规则作为本次细化建议，评审确认后才能成为正式采购验收算法；第一版不自动选择跨 SKU 的资金分配方案。

## M07 输出 人工确认与验收

### 输出

采购补货方案包括店铺、SKU、规格、货源、预测版本及期间、采用情景、库存与在途明细、预计缺货和可售日期、建议数量、起订箱规、单价、采购与物流金额、资金需求、缺项和风险。方案标识“含测试数据”并能追溯测试字段。

状态为生成中、待补充、待确认或已确认等业务结果。人工调整后的数量、金额、理由、操作人和确认时间形成独立版本；已确认方案可查阅，不自动生成供应商订单、付款或真实在途。

### 人工确认点

首次选择库存策略和预测情景、关键输入缺失、预算或交期冲突时由运营判断。每份采购方案最终都需有权限的人确认。输入变化后先复核或重算再确认；确认只是保存采购决定，执行继续在线下进行。

### 验收标准

| 编号 | 给定条件与动作 | 通过标准 |
| --- | --- | --- |
| M07-A01 | 缺少可用预测，或预测只覆盖 30 天而采购需要 120 天。 | 联动 M06 或列待确认，不能直接采用不适配的销量数生成可确认方案。 |
| M07-A02 | 第 4 天预计缺货，测试在途第 8 天可售。 | 保留第 4—7 天缺货风险，不把第 8 天在途提前计入当前库存。 |
| M07-A03 | 按建议算法，到货后需求 300、安全库存 20、到货前预计可用 80、期内其他有效在途 50。 | 基础需求为 190；若 MOQ 为 100、箱规 24，则建议 192。此用例在算法获确认后生效。 |
| M07-A04 | 上述建议 192 件，单价 20、物流总计 300、预算 4000，币种相同。 | 资金需求 4140、超预算 140，列出冲突待确认；不静默提交超预算或改变数量。 |
| M07-A05 | 新品等待到货 90 天，之后覆盖期需求 300、安全库存 20，无库存或在途。 | 按建议算法基础需求为 320；未到货的 90 天潜在销量不累加。库存足够时需求最低为零，不因 MOQ 强制采购。 |
| M07-A06 | 人工改数量或确认前真实库存已更新。 | 重算相关金额、箱规和缺货判断，提示变化并保留原版本。 |
| M07-A07 | 最终确认一份含测试在途与成本的方案。 | 保存确认人、版本和含测试标识；真实库存不增加，也不把建议数记为真实在途。 |

## M08 智能问数 Agent

对应基础需求：QA-01 至 QA-07。

### 输入

| 输入 | 来源与约束 |
| --- | --- |
| 问题与上下文 | 自然语言问题、当前会话及已明确的店铺、商品、日期和对比条件；新会话不沿用上一会话条件。 |
| 访问范围 | 当前成员有权访问的店铺和数据；提问不能扩大成员权限。 |
| 指标口径 | 统一的销量、销售额、订单、库存、广告、利润及业务状态定义；未确定的指标不能由模型临时发明口径。 |
| 可用业务数据 | M01—M07 的事实、公开参考、预测与方案记录，带来源、时间、版本和测试标识。 |

### 处理流程

1  理解问题。识别查询对象、指标、时间、筛选及对比条件，结合本会话上下文补充已确定信息。相对日期必须转换成明确起止日期展示。

2  处理歧义。“销量下降”缺少比较期、“利润”未明确实际还是测算时，提示用户选择；不能悄悄换成容易取得但含义不同的指标。

3  读取并计算。只查询权限范围内数据，使用统一指标口径和计算工具完成聚合、排序、对比。查询失败、无数据和数值为零分别处理。

4  生成解释。模型根据查到的结果组织结论、表格或图表，展示筛选条件和截止时间。原因推测单列，不能把相关变化直接写成已证实因果。

5  支持追问。下一问继承仍适用的店铺与日期条件；用户明确改变条件时更新并展示。删除会话仅处理会话记录，不删除底层经营资料。

6  识别操作请求。用户要求改价格、改库存或下采购单时，不执行写入，指向对应模块的人工确认流程。

### 首批指标口径

真实售出件数和订单数分别统计，销售额须说明商品金额、运费及退款是否纳入；可售库存使用 M02 的状态口径。选品利润沿用 M03 测算，实际经营净利润须具备实际收入费用。未接入的广告或费用指标显示未接入；含测试成本的利润不得命名为已核实实际净利润。

建议待确认：默认“上周”采用店铺业务时区的上一自然周；“下降”默认不擅自选择环比或同比，而由首次提问时确认并在本会话内沿用。

## M08 输出 人工确认与验收

### 输出

输出简要结论、必要的表格图表、支撑明细入口，以及使用的指标定义、条件、比较期间、来源、截止时间和数据质量。答案中的数值能追溯到同一查询结果；预测、实际、测算和测试金额明确区分。

提供会话历史、新建查询、快捷问题、查询进度和结果明细入口；会话保留时长与数量可配置。会话和查询记录保存所用条件，方便复查答案。

### 人工确认点

提问存在店铺、日期、指标或比较范围歧义时，由提问者澄清；首次使用尚未定稿的利润等口径时，由业务负责人确认指标定义。普通只读查询不逐次审批。需要执行业务操作时进入相应模块确认，不在问数中替代发布或采购决策。

### 验收标准

| 编号 | 给定条件与动作 | 通过标准 |
| --- | --- | --- |
| M08-A01 | 问某店上周销量，再追问哪些商品下降最多。 | 沿用已确认店铺和时间；比较期间未确定时先澄清，返回的差值可与明细核对。 |
| M08-A02 | 一张订单购买商品 A 两件、B 一件。 | 按已选订单口径返回订单数 1、售出件数 3，不把订单数当销量。 |
| M08-A03 | 问某品为什么被排除。 | 返回对应选品记录、原因、证据和时间，不自行补造新的排除原因。 |
| M08-A04 | 广告接口未接入，或利润计算引用测试成本。 | 前者显示未接入；后者清楚标为含测试的测算，不输出虚构实际广告额或净利润。 |
| M08-A05 | 跨美元与人民币金额要求合计。 | 已有批准换算口径才汇总并显示汇率；否则分币种展示或询问，不能直接相加。 |
| M08-A06 | 成员 A 只能看店铺 A，却问全部店铺数据。 | 只在授权范围查询并说明范围，图表和明细均不泄露其他店铺。 |
| M08-A07 | 要求“把价格降到 20 美元”，或删除会话。 | 前者不执行写入并指向业务模块；后者不影响底层销售、库存和采购记录。 |

## M09 经营驾驶舱 Agent

对应基础需求：BI-01 至 BI-06。

### 输入

| 输入 | 来源与约束 |
| --- | --- |
| 看板需求 | 自然语言目标、指标、时间范围、店铺范围和展示偏好；也可从已有看板草稿继续编辑。 |
| 统一指标与数据 | 与 M08 共用指标定义、权限和来源。真实销售、业务进度、预测及测试测算分别标识。 |
| 组件与布局 | 可用指标卡、表格和趋势图等组件，以及颜色、位置、尺寸和终端预览配置。首批清单待确认。 |
| 发布配置 | 看板名称、可见人员或团队、当前草稿和发布版本、刷新频率及各组件数据截止时间。 |

### 处理流程

1  生成草稿。根据自然语言匹配已有指标和组件，形成布局建议。指标未接入时显示数据缺口，不能生成假数填满看板。

2  编辑和预览。支持拖拽、调整大小、图表样式和颜色，预览电脑、平板、手机效果。AI 可解释指标，但解释必须基于同一批实际结果。

3  校验发布内容。检查组件的字段、权限、数据来源和时间；显示不可用指标。设计修改保存在草稿，不改变当前团队看到的已发布布局。

4  人工发布。有权限的人核对内容、可见范围和预览后发布布局版本。发布只影响看板展示，不触发商品上架或采购。

5  刷新数据。发布版布局保持稳定，按配置重新取可用数据并标明业务截止时间。页面刚刷新不代表来源刚采集，不能把 24 小时采集包装成实时销量。

6  隔离异常。单组件失败时显示失败及旧值时间，其他组件继续更新；解释需要跟随相同数据版本，不能用旧解释描述新数值。

建议待确认：首批看板分为商品开发、内容与发布、销售库存、预测采购四个区域；费用利润仅在具备明确来源和标识时加入。具体默认布局与是否允许个人看板另行确认。

| 编号 | 给定条件与动作 | 通过标准 |
| --- | --- | --- |
| M09-A01 | 用自然语言要求销量、库存和待审采购看板。 | 生成关联真实指标的可编辑草稿，可拖拽并预览；未接入项明确标识。 |

## M10 公共管理与任务审核

对应基础需求：CM-01 至 CM-07。

### 输入

| 输入 | 来源与约束 |
| --- | --- |
| 成员和权限 | 内部独立账号、可见店铺及可执行动作；发布确认、采购确认、参数维护分别可授权。具体成员分工待定。 |
| 业务配置 | 查询、筛选、利润、报价、渠道、广告仓储、预测补货、内容视频及同步等参数；附单位、范围和生效状态。 |
| 任务与依赖 | 任务所属商品和店铺、输入版本、执行步骤、外部返回、所需人工问题及已完成结果。 |
| 人工操作 | 补充事实、审核决定、恢复、重试、选用素材、发布或采购确认，以及修改理由。 |

### 处理流程

1  校验访问与操作。每次查看数据、创建任务或确认结果都检查人员和店铺权限；授权凭据只用于连接，不进入普通日志、导出或错误说明。

2  维护配置。展示参数含义、单位、适用范围和当前值，检查取值合法性。保存新版本及操作者；平台硬限制和有效费用规则不允许作为随意业务数值绕过。

3  固定任务版本。新参数只对后续新任务生效。历史结果和运行中任务保留启动版本；人工复查创建关联新任务，不能覆盖旧判断。

4  调度和暂停。步骤满足输入条件时自动执行，外部失败保存原因和已完成结果；关键事实不明时进入待人工并列出恢复需要的内容。

5  恢复和重试。确认问题后从受影响环节继续，提交类动作先核对远端是否已成功。任务重复执行不得重复产生商品、素材或确认方案。

6  处理多人修改。确认前核对最新版本，发生并发修改时提示差异并重新选择；保留操作记录，不无提示覆盖他人结果。

建议待确认：一个选品或内容流程内自动派生的子任务继承父任务配置；明确创建独立新任务时采用当时配置。商品单独设置优先于全局默认，临时任务覆盖须显示实际采用值及来源。

## M10 输出 人工确认与验收

### 输出

输出成员与权限记录、带版本的参数、任务列表与详情、待人工事项、重试记录和操作日志。每个结果能回到所用输入及配置；每个待确认项能看到负责人或有权处理人员、所需材料和恢复步骤。

### 人工确认点

授权管理人员确认成员和店铺权限；运营维护并保存业务参数；有权限的人员处理各模块待确认项。发布和采购保持各自独立确认，不增加未经约定的多级审批。备份留存、任务并发、通知方式及资源预算待方案设计确定。

### 验收标准

| 编号 | 给定条件与动作 | 通过标准 |
| --- | --- | --- |
| M10-A01 | 任务 A 已按利润门槛 30% 启动，随后全局改为 35%，再建任务 B。 | A 保留 30%，B 使用 35%；历史商品不批量重跑，两个结果可查看各自版本。 |
| M10-A02 | 人工恢复一个历史商品，重新发起选品。 | 新建关联任务并采用该任务的有效参数，旧核价、排除原因和确认记录仍可查看。 |
| M10-A03 | 商品广告费单独设 8%，全局默认由 10% 改为 12%。 | 既有单品明确设置不被静默覆盖；新任务展示实际使用 8% 及来源。 |
| M10-A04 | 费用单位填错，或未给售价便进行利润运算。 | 配置或计算校验失败并说明问题，不能生成无效利润率后宣布通过。 |
| M10-A05 | 搜图成功、后续检索失败，再次重试。 | 保留可用的搜图结果，从适当步骤恢复；不重复创建无关联副本。 |
| M10-A06 | 两人同时编辑同一方案，其中一人先确认。 | 另一人看到版本已变化，需复核后保存；已确认结果不被静默覆盖。 |
| M10-A07 | 无发布权限人员尝试确认发布或查看其他店铺。 | 相应操作和读取被拒绝；操作记录可审计，普通错误信息不泄露凭据。 |

### 跨模块验收

E2E-01  新品内容与发布。真实采集一条商品，经过货源、利润和风险资料核对，由人工选中；生成八类内容并审核；实际保存平台草稿，未经确认不发布。每一步引用同一已确认商品规格，失败可定位恢复。

E2E-02  在售商品补货。真实同步销量与库存，生成覆盖采购周期的预测，结合明确标记的测试成本及在途形成方案；人工改量后金额和约束重算，确认后真实库存不变。

E2E-03  参数版本。任务执行中调整利润门槛；旧任务、历史结果和已确认方案保持原版本，新任务使用新版本。问数与看板能够展示相同记录及数据性质。

E2E-04  数据与权限。模拟一个外部来源失败、一个测试字段和一个无权限店铺；任务、问数和看板一致显示失败、测试影响与访问限制，不产生虚假的零值、实际利润或全量成功。
