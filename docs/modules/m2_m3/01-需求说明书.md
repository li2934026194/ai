# CrossPilot · 经营分析与智能问数模块（M2·M3）需求说明书

> **文档状态**：V1.0 正式基线（对齐《AI跨境电商平台-模块需求细化_V1.1》M01/M08/M09、《SRS V1.0》QA-01~07 / BI-01~06 及原型 `docs/prototypes/web/pages_m0_m3.js`）
> **适用范围**：首页岗位工作台（`/home`）、M2-1 广告投放与预算调节（`m2a`）、M2-2 正式经营大屏浏览（`m2b`）、M3-1 竞品监控与舆情分析（`m3a`）、M3-2 经营智能问答助手（`m3b`）

## 1. 模块定位、三方映射与核心原则

### 1.1 业务目标

M2 与 M3 共同组成 CrossPilot 的**全链路经营核算中心、广告调控台、竞品舆情雷达与只读智能问数助手**。解决跨境管理层与运营团队的四大难题：
1. 各平台订单、采购成本、广告支出、售后退款和采购承诺资金分散在不同表，财务与运营各算各的账（口径不一致）；
2. 演示测试店订单或测试成本被误混入真实 GMV 与实际净利润，误导经营决策；
3. 竞品调价、BSR 波动与差评痛点缺乏统一看板，难以及时反哺 M4 选品与 M7 文案；
4. 业务人员想用自然语言查数时，担心大模型胡编数字或执行修改/删除底层数据的危险操作。

### 1.3 上下游接口契约

- **上游只读聚合源**：
  - M0：`M0Order`（订单 GMV 与销量）、`M0Product`（单件采购成本）、`M0Inventory`（当前可售）、`M0Shop`（已连接店铺数）；
  - M1：`M1AftersalesTicket`（已批准售后退款金额 `APPROVED` 与待审批工单计数）；
  - M5/M6：`M5SalesHistory`（30 日日销趋势）、`M6PurchaseOrder`（在途非取消采购单承诺资金）、`M6AlertEvent`（未确认断货预警）。
- **下游赋能**：向管理层输出跨部门唯一财务利润口径；M3 竞品痛点反哺 M4 选品决策与 M7 文案卖点优化；M2 异常指标支持直接钻取到 M3-2 追因。

### 1.4 六项核心业务原则（硬约束）

1. **同一口径字典（Single Metric Truth）**：经营大屏与智能问数共用后端同一计算逻辑，不允许前端自己按一套口径算、后端问数按另一套口径算。
2. **实盘订单与演示数据隔离**：统计实盘 GMV 与利润必须严格过滤 `is_mock == False`（V1.1 明确加固过滤条件），含测试成本或估算项必须显式声明。
3. **跨币种不直接混加**：USD（GMV/广告/退款）与 RMB（采购承诺资金）必须分栏分币种展示，或经明确汇率参数折算后标明汇率依据，绝不允许美元和人民币直接相加。
4. **未接入来源诚实标注，绝不填零充数**：未对接外部结算报表或广告实时同步时，明确标出核算口径与估算比例（V1 佣金 15% 参考口径），不能把外部缺失写成零消耗或实盘已到账。
5. **只读智能问数安全守卫（Write-Block）**：M3-2 绝对禁止执行改价、删单、改库存、下采购单等写意图；遇到此类指令立即阻断、写入审计并引导前往对应业务模块人工确认。
6. **大屏浏览者与操作权分离**：`manager` 具备全局只读浏览权，但不能直接越权修改广告出价或篡改竞品数据；写操作权限精准收敛至 `planner` / `bi_analyst`。

## 3. 分页详细功能需求

### 3.1 首页工作台（`/home`）

1. **6 项实时 KPI**：在营 SKU 数、已连接店铺数、累计 GMV（USD）、未确认断货告警数、待审补货数、待审售后退款数。
2. **4 项跨模块必办事项流转卡**：动态统计 M4 选品待审、M6 补货待审、M7 上架合规包（指向 `/m7/compliance`）、M1 售后待审（含实际待办数量），点击一键直达对应页。

### 3.2 M2-1：广告投放与预算调节（`m2a` / `/m2/ads`）

1. 展示广告计划（`campaign_name`）、SKU、渠道、7 日花费/归因销售额、ACOS、ROAS、日预算与当前状态（`ACTIVE`/`PAUSED`）。
2. 在线输入新日预算（`> 0`）并切换启用/暂停，提交后更新数据库并记入审计 `AD_ADJUSTED`，同时影响 M2-2 净利润扣减项。

### 3.3 M2-2：正式经营大屏浏览（`m2b` / `/m2/overview`）

1. **财务总览卡**：总 GMV、预估净利润（`SKU净利之和 - 7日广告花费 - 已批售后退款`）、毛利率 %、7 日广告与已批退款对比、M6 非取消 PO 采购承诺资金（RMB）。
2. **单 SKU 盈利拆解表**：按 SKU 汇总销量、GMV、COGS + 15% 平台佣金、单品净利。
3. **30 日销量趋势与多渠道结算对账表**：从 `m5_sales_history` 聚合 30 天趋势，分渠道展示 Amazon US / TikTok Shop US 结算状态（`SETTLED`/`PENDING_PAYOUT`）。

### 3.4 M3-1：竞品监控与舆情分析（`m3a` / `/m3/competitors`）

1. 展示竞品品牌、ASIN、竞品售价、BSR 排名、评分、正面情感占比与高频差评痛点标签（`negative_topics`）。
2. `bi_analyst` 可新增竞品 ASIN 监控（`price_usd > 0`, `rating 1.0~5.0`, `bsr_rank >= 1`），记录 `COMPETITOR_ADDED` 审计。

### 3.5 M3-2：经营智能问答助手（`m3b` / `/m3/ask`）

1. **快捷问题与自由提问**：支持常见经营提问查询实时指标。
2. **只读安全拦截与溯源声明**：检测写入关键词（`delete / drop / update / insert / 修改 / 删除`）立即拒绝；合法查询显式标明「【口径溯源：M0 实盘订单 + M2 广告/成本 + M6 告警中心】」。
3. **V1.1 服务端升级规划**：在后端新增 `POST /api/v1/orgs/{org_id}/m3/ask`（`require_perm("m3:ask")`），由服务端执行安全只读查询聚合、记录问数与写拦截审计事件。

## 5. 非功能需求与验收标准

### 5.1 性能、准确率与安全指标

1. **聚合响应基准**：跨 6 模块聚合 `GET /m2/overview` 与 `GET /home/workbench` P95 ≤ 150ms；广告调价与新增竞品 P95 ≤ 80ms。
2. **口径一致率**：M2-2 大屏、首页工作台与 M3-2 问数输出核心财务数字 100% 一致；除零边界（0 GMV）安全返回 `0.0%` 不报 500。
3. **安全拦截率**：M3-2 写意图拦截率 100%；`manager` 只读拦截写操作 100%。

### 5.2 核心验收标准矩阵（M2M3-AC-01 ~ M2M3-AC-05，对齐 M08/M09-A01~07）

| 验收编号 | 对应老师用例 | 给定条件与动作 | 通过标准 |
|---|---|---|---|
| **M2M3-AC-01** | M09-A05 | 在 M1 批准 `$25` 退款或新增 M6 非取消 PO 后刷新 M2-2 | `approved_refund_usd` 增加 `$25`、净利润等额扣减；`po_commitment_rmb` 实时增加 |
| **M2M3-AC-02** | M08-A04 | 向 `m0_orders` 写入 `is_mock=True` 订单并查看 M2-2 | V1.1 加固过滤后实盘 GMV 不含模拟订单，多币种（USD 与 RMB）分栏展示不混加 |
| **M2M3-AC-03** | M08-A07 | 在 M3-2 输入「把 SKU-00704 改价为 1 元」或 `DELETE FROM orders` | 被只读安全守卫拦截拒绝，底层数据库零变更 |
| **M2M3-AC-04** | M09-A07 | `manager` 浏览 M2-2 成功，但调用广告调价或新增竞品接口 | `GET /m2/overview` 返回 200；写接口均返回 `403 M7-4031` |
| **M2M3-AC-05** | M08-A01/02 | 查数回答明确区分总 GMV、净利、7日广告花费与未确认告警数 | 与 M2-2 大屏底层数据源数值 100% 一致，附带口径溯源 |

2. **V1.1 精修规划**：修复 `todo-m7` 跳转 `/m7/compliance`、全量强制过滤 `M0Order.is_mock == False`、以及服务端落地 `POST /api/v1/orgs/{org_id}/m3/ask` 写拦截与审计闭环。
