## 1. 模块定位、三方映射与核心原则

### 1.1 业务目标

M8 是 CrossPilot 平台的**组织治理、访问控制与安全审计底座**。跨境电商团队通常涉及选品、内容设计、客服、仓管、运营、BI 分析师、主管与管理者等多角色协作，若缺乏刚性权限隔离与留痕机制，极易出现：
1. 普通员工绕过审批给自己开通主管权限或修改线上合规/价格参数；
2. 业务单据由同一个人「自提自批」（如自己提交补货或退款单自己批准）；
3. 测试联调账号（`mock_buyer`）误看或误改真实店铺订单与采购数据；
4. 发生资金或线上事故后，无法用人话追溯「谁在何时对哪张单据做了什么操作、为何被放行或拦截」。

### 1.4 五项核心治理原则（硬约束）

1. **禁止自批与职责分离（SoD）**：M0 成本改价、M1 售后退款、M4 选品过会、M6 补货审批、M7 发布放行五大敏感审批流，必须强制核验「发起人 ≠ 审批人」（`M7_STRICT_SEPARATION_OF_DUTIES=true`），同人自批一律返回 `403 M7-4032`。
2. **权限矩阵只读透明 + 越权必留痕**：M8-2 的权限矩阵仅供只读核对，绝不允许直接在页面点选绕过后端权限校验；任何岗位触发 `403` 拦截时，即使请求失败回滚，底座依然独立提交写入 `core_audit_events` 中文拦截记录。
3. **多租户硬隔离（`org_id`）**：JWT 或请求头中声明的 `actor_org_id` 必须与请求路径 `{org_id}` 严格一致，否则直接拒绝跨组织访问（`403 M7-4031`）。
4. **双模式身份认证与凭证零泄露**：线上生产走账号密码登录签发 `HS256 JWT`（V1.1 补齐 `/auth/login` 与密码哈希）；本地演示支持侧边栏切换 9 岗位 Header 模式；所有异常与日志经过 `redact_secrets` 脱敏，绝不吐出密钥或 Token。
5. **配置与参数版本向前生效**：组织级审批策略切换仅影响新审批动作，历史单据与历史审计记录保持原决策依据不可篡改。

## 3. 分页详细功能需求

### 3.1 M8-1：员工名册与岗位授权（`m8a` / `/m8/users`）

1. **成员列表展示**：工号 (`user_id`)、员工姓名 (`display_name`)、企业邮箱 (`email`)、所属岗位徽章、在职状态（`在职启用` / `已停用`）、入册时间。
2. **新增成员授权**：
   - 必填：`user_id`（组织内唯一，重复抛 `409 M7-4091`）、`display_name`、`role_code`（必须是 9 大标准角色之一，否则 `422`）、`email`。
   - 仅 `manager` / `approver`（权限码 `m8:manage`）可创建，创建同时写中文审计 `USER_CREATED`。
3. **在线调岗与账号启停**：支持变更员工 `role_code` 及切换 `is_active`；写入 `USER_UPDATED` 审计句，且不改写该员工历史上在其它模块留下的审批/操作签名。
4. **V1.1 迭代规划**：新增真实登录页（`LoginView.vue`）与 `POST /api/v1/auth/login` 接口、为 `m8_users` 扩展 `password_hash` 与 `allowed_shop_ids`（店铺级行级数据范围绑定）。

### 3.2 M8-2：岗位权限矩阵与审计（`m8b` / `/m8/roles`）

1. **九大岗位权限矩阵（只读）**：表格展示 9 个角色编码、中文名称、职责说明及完整权限码列表（`m0:*` ~ `m8:*`）。
2. **五大审批流策略台账（`M8ApprovalPolicy`）**：展示各模块审批策略名称、触发阈值规则、审批岗位、是否强制 `enforce_sod`（禁自批）及启用状态；支持 `m8:manage` 人员切换策略并写 `POLICY_TOGGLED` 审计。
3. **全平台中文操作审计台账**：
   - 支持按模块筛选（全部 / `M0` / `M1` / `M2` / `M3` / `M4` / `M5` / `M6` / `M7` / `M8` / `RBAC`）。
   - 每行显示：发生时间、所属模块、动作标识、执行状态（`允许` 绿标 / `拦截` 红标）、操作人及角色、关联 SKU、完整中文句子（`sentence_zh`）与链路 `trace_id`。

## 5. 非功能需求与验收标准

### 5.1 性能、安全与可用性指标

1. **鉴权与拦截延迟**：每次请求 `get_actor_context` + `require_perm` 校验开销 ≤ 2ms；审计台账分页检索 P95 ≤ 60ms。
2. **安全拦截率**：越权操作、跨租户请求、停用账号访问拦截率 100%，且拦截审计记录独立提交成功率 100%。
3. **脱敏与不可篡改**：日志脱敏 `redact_secrets` 覆盖率 100%；前端不提供任何删除或修改历史审计的接口。

### 5.2 核心验收标准矩阵（M8-AC-01 ~ M8-AC-06，对齐 M10-A01~A07）

| 验收编号 | 对应老师用例 | 给定条件与动作 | 通过标准 |
|---|---|---|---|
| **M8-AC-01** | M10-A01 | 查询 `/m8/roles` 与 `/m8/policies` | 精确返回 9 个角色及其权限码集合、5 大模块默认开启 `enforce_sod=true` 的审批策略 |
| **M8-AC-02** | M10-A07 | 无 `m8:manage` 权限角色（如 `planner`/`cs`/`creator`）新建或修改员工 | 返回 `403 M7-4031`，且 `/m8/audits?module=RBAC` 留存完整中文越权拦截记录 |
| **M8-AC-03** | M10-A07 | `mock_buyer` 尝试访问 M0/M2/M4/M5/M6/M7/M8 任意只读或写入接口 | 全部返回 `403`，仅 `/m1/simulator/ask` 允许调用 |
| **M8-AC-04** | M10-A07 | 携带 `X-Actor-Org-Id: org_other` 访问 `org_demo` 资源 | 租户门禁立即抛出 `403 M7-4031` |
| **M8-AC-05** | M10-A02 | 对员工调岗或停用，检查历史审批单与审计记录 | 调岗写入新审计事件 `USER_UPDATED`，历史单据原经办人签名与审计句不被篡改 |
| **M8-AC-06** | — | 日志或异常文本中意外出现 `sk-xxx` 或 `Bearer xxx` 凭证 | 经 `redact_secrets` 脱敏为 `***REDACTED***`，普通错误信息绝不泄露真实密钥 |

## 6. 已确认的技术落地口径（V1 实施方案拍板）

1. **V1 双模身份鉴别**：兼容生产 `Authorization: Bearer <HS256 JWT>` 与本地安全开关控制的 Header 演示切岗模式（`X-Actor-User-Id`/`X-Actor-Role`/`X-Actor-Org-Id`），`X-Trace-Id` 全链路贯通。
2. **V1.1 安全增强**：补齐真实登录页与 `POST /api/v1/auth/login` 密码哈希验证、`is_active=False` 停用账号拦截以及 `allowed_shop_ids` 店铺级行权限数据过滤。
