0.1 编写目的与依
据
本文把源文档的讲解性描述转换为可评审、可开发、可验收的规范性需求，用于统一产品、后端、前端与测试对范围、口径与边界的理解。
唯一需求来源为《AI跨境电商平台V1.0.docx》。源文档包含 7 个 Agent 模块，每个模块按「目标 / 业务流程图 / 数据流向图 / 类图 / 用例图 / 时序图 / 展示效果 / 实现步骤」组织。本文按源文档章节编号标注每条需求的出处，便于追溯与评审。

源文档表述类型
本文处理方式

转为

，编号 BR-* / 第 12 章

转为业务规则，编号 BR-*
「测试桩数值仅用于证明刷新行为」等验收说明

1 项目概
述
1.1 建设目
标
在不越过平台合规红线、不把估算或演示数据当作真实经营事实的前提下，把跨境电商运营中「客服应答、经营看数、选品研究、销量预测、补货决策、内容生产」六个环节串成可追溯、可审计、可人工把关的工作链路。系统需让使用者随时回答四类问题：
数据来自哪里、哪些指标可算、哪些仍是未知、谁批准了下一步
（§4.1）。
贯穿全局的价值主张（§1.1、§2.1、§3.1、§5.1、§6.1、§7.1）：
把分散的上下文收进同一会话或同一计划，减少凭记忆操作与误判。
把「搭建/分析」能力交给业务人员，降低对开发排期的依赖。
把确定性计算、规则判断和最终审批留在服务端与人员手中，AI 只做解释、建议或文案。
把「演示/估算/未知/已核验」显式区分，未知值保持空值，不默认为零。

3.1 模块目标与边
界
把售前商品依据、买家来信、人工回复、售后订单核验与内部审批放在同一会话上下文中，使客服可追溯「推荐了哪个商品、依据是什么、买家说了什么、核验了哪笔订单、谁批准了工单」，同时提供无需向真实买家发消息的可重复演示环境（§1.1）。

7.3 指标口
径
编号
口径
BR-FC-01
WAPE = Σ\
实际销量 − 预测销量\
÷ Σ实际销量 × 100%，越低越好；示例 10+20+20 与 100+200+300 得 8.33%
BR-FC-02
参考评价区间（业务管理参考，非行业通用标准）：≤5% 非常优秀；5%–10% 优秀；10%–20% 良好；20%–30% 一般；>30% 较差
BR-FC-03
MAE 衡量平均差多少件；RMSE 对大误差惩罚更明显；MAPE 衡量每点相对误差；WAPE 衡量整体销量偏差；Bias 判断整体偏高或偏低。WAPE 相比 MAPE 不易被低销量商品的百分比误差过度影响
BR-FC-04
闭环链路为：历史订单 → 销量预测 → WAPE 模型评估 → 库存与交期分析 → 智能补货 → 实际销量回流 → 模型持续优化
