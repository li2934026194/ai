# 严格业务风控、9角色权限矩阵与现实优化设计（V2）

> 对应流程图目录：`docs/prototypes/modules/`（`m00_rbac_matrix.png` + `m01_shop.png` ~ `m13_kb.png`，共 14 张 PNG）  
> 设计原则：**凡涉金钱与对外发布必设人工审批门禁、提案与审批强制分离（SoD）、管理权与资金权分离、未知不填零、全链路不可篡改审计**。

## 一、企业级 9 角色权限矩阵（基于现有 6 角色升级）

> 与现有代码 `pilot/rbac/service.py`（`viewer / planner / approver / warehouse / auditor / admin`）兼容映射，补齐跨板块业务岗位：

| 岗位角色 | 对应现有 RBAC | 核心职责边界 | 严禁越权红线 |
|---|---|---|---|
| **1. 老板 (`owner`)** | 新增（终审级） | 全局只读全盘经营/现金流/净利润；终审大额补货（`>$20,000`）、大额退款、超额度测款、店铺授权/解绑、月度封账、高敏权限复核 | 保留常规操作留痕，所有终审写不可篡改审计日志 |
| **2. 财务 (`finance`)** | 新增（资金/账务） | 全权管理【财务利润】（费用导入、CostCard 锁版、汇率结算、月度封账）；会签中大额补货（`$3k~$20k`）、复核选品利润率、审核大额退款/打款；只读经营总览与问数财务口径 | **禁止**发客服消息、发商品内容、修改商品上架文案、自建采购收货、配置 RBAC 权限 |
| **3. 运营主管 (`ops_manager`)** | 映射 `approver` | 审批所辖店铺的【选品初筛】、【内容发布】、【销量预测人工修正】、【常规补货 `≤$3,000`】、【商品下架/特批改价】 | **禁止**自批自己提交的申请（SoD）；无权修改 CostCard 与公司总利润封账 |
| **4. 运营专员 (`operator`)** | 映射 `planner` | 导入选品、维护商品基础信息、生成内容草稿送审、提交预测调优申请、提交补货方案（`READY_FOR_REVIEW`） | **绝对禁止**自提自批；调价低于保本线硬拦截；看不到公司整体净利润 |
| **5. 采购仓配 (`warehouse_buyer`)** | 映射 `warehouse` | 执行已批准 PO 下单、物流登记、分批收货质检上传凭证、提交库存盘点单 | **禁止**审批补货单、修改采购单价/数量、查看公司总利润与广告费 |
| **6. 客服 (`cs_agent` / 主管)** | 新增 | 查看脱敏订单、知识库检索、AI 辅助起草并确认回复、创建售后工单（客服主管可批小额赔付，大额转财务） | **严禁**看公司采购底价与净利润；问数询问利润直接拒绝；高风险投诉强制切人工 |
| **7. 合规负责人 (`compliance`)** | 新增 | 维护【合规规则库】（发布/回滚禁用词、类目认证矩阵、AI 人物标注规范）；高风险内容与选品合规一票否决；审核【知识库】退货政策文档 | 不参与日常花钱采购与资金审批 |
| **8. 系统管理员 (`sys_admin`)** | 映射 `admin` | 创建普通账号、绑定店铺技术 Token 与同步调度、配置菜单与基础参数 | **三权分立**：不能看公司净利润、不能审批任何金钱单据、不能自授「老板/财务/审批」高敏角色（须老板二次复核）、不能删改审计日志 |
| **9. 审计员 (`auditor`)** | 保留 `auditor` | 全局只读全业务单据流痕、审批记录、权限变更 Diff、智能问数执行记录 | **全系统零写权限**，独立监督包含老板/财务/管理员在内的所有操作 |

### 四大内控铁律

1. **铁律 1（SoD 提案≠审批）**：`created_by != approved_by`，系统后端强制校验，任何提交人不得批准自己的选品/内容/补货/退款申请。
2. **铁律 2（金钱三级审批）**：
   - `≤ $3,000`：运营主管审批；
   - `$3,000 ~ $20,000`：运营主管 + 财务会签（核现金流与 CostCard）；
   - `> $20,000` 或激进高风险/大额赔付单：必须老板（Owner）终审。
3. **铁律 3（管理权与资金权分离）**：系统管理员不管钱、不看总利润、不删日志；授予高敏角色必须老板二次确认。
4. **铁律 4（实时查库鉴权 + 按角色脱敏）**：不信任 JWT 旧快照，离职停用毫秒级失效；客服/运营/管理员在经营总览与智能问数中被自动屏蔽公司总净利润与采购底价。
