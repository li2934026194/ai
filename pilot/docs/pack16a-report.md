## 一、起因：查 σ 时先撞到一个更严重的隐藏 bug

派单原本只要求把 σ_日 从"全样本拟合残差"改成"回测各窗口样本外合并残差"，并把 `ar1` 死参数接上。只读勘查 `core/backtest.py` 时发现真正的问题不在 σ：

```python
for w in windows:
    for name, fn in models.items():
        yhat[name].extend(fn(train, horizon))
        y_all.extend(test)          # ← 写在模型循环内
```

`y_all` 在一个窗口里被 4 个模型各扩一遍实际值，而每个模型的预测只扩一遍。从第 2 个窗口开始，`zip(y_all, yhat)` 的两侧就不是同一个日期——**对外的 WAPE / bias / MAE / 最优模型选择，全部建在错位数据上**，而 σ、建议量又建在"最优模型"上，误差一路传到补货量。记为 **I-26**（严重度高于 I-08/I-09）。

## 五、为什么新 σ 反而更小（与我的预判相反，必须写清）

我先前判断"样本外残差通常更大、建议量会往上走"，实测反向。原因是旧口径的残差不是"拟合优度残差"，而是**全样本模型对历史逐点的偏差**：

1. `croston_sba` 不是最小二乘拟合，参数不是为压低 SSE 选的，全样本回看不保证残差小；
2. 全样本预测把"整段历史都见过"的水平去对每一天，早期冷启动段偏差被计入 σ；
3. 新口径是滚动样本外（每窗只用窗口前数据、预测后 14 天），残差是"当时真能犯的错"，在需求平稳、季节稳定的序列上通常小于全样本回看偏差。

结论方向：**σ 变小、建议量下调**（420→360），不是系统变激进，而是去掉了被高估的波动。这条会改变所有已对外公布的补货量数字，必须同步文档与契约（见第七节）。
